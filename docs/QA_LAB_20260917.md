# Real OPNsense lab qualification — 1.15.1

## Environment and boundary

Two temporary OPNsense 26.1.2_5 VMs, 4 GiB RAM and 20 GiB disk each, restored from backup and sanitized before use. Three bridges have no physical uplinks or host addresses. Separate management, WAN client and LAN server namespaces have only lab routes. Scoped host firewall rules block routing between the lab and other networks. Production remains `read_only:true` throughout.

The real plugin handlers, HTTPS client and browser use the two real firewall APIs. The lab replaces only the PegaProx authentication boundary with an SSH-protected adapter; production authentication is covered separately by its authenticated read-only smoke. Lab credentials and machine details are kept outside this repository in the encrypted vault.

## Findings reproduced and corrected

1. Local apply/reconfigure does not trigger XMLRPC in 26.1.2. The original request saved on A and returned `409 ha_unverified`, correctly detecting absence on B. Explicit, opt-in `xmlrpc_pf` synchronization now performs the guarded native action and peer readback.
2. XMLRPC retains the final DNAT on B when deleting it removes A's entire `nat/rule` branch. The first deletion returned `409`, not a false success. Exact-UUID cleanup now requires matching initial revisions and single-rule inventories, unchanged peer contents and safe HA; absence is verified on both nodes.
3. DNAT search adds generated anti-lockout rows without increasing `total`. A truncated response could therefore look complete. Codex identified the case; a regression failed before the fix and passed after counting only real DNAT rows for completeness.

Lab setup corrections: permit CARP on WAN, regenerate cloned host identities, and enter both host mount and network namespaces when starting a VM from the test runner. These changes affect only the temporary lab.

## Storage durability limit

An immediate hard stop after acknowledged updates lost recent changes on A, while B retained them. The restored system uses ZFS with a 90-second transaction interval; OPNsense's configuration save flushes its userspace buffer but does not call `fsync`. The first recovery required reconciliation. Subsequent power-loss tests used an explicit storage barrier on both nodes and recovered automatically. A successful plugin readback is not a guarantee against immediate power loss; the plugin does not change storage tuning or upstream code.

## Review and release decision

Codex reviewed the frozen artifact and found one P2 (DNAT completeness), subsequently fixed and closed. No open P0/P1/P2 remain in that review. The new Fable invocation returned HTTP 429, “out of usage credits”, before model execution. **The 1.15.1 correction has not completed dual-family review.** The earlier 1.15.0 panel does not cover this delta.

Release may be deployed with production still read-only. Enabling production writes requires a separate operational decision, qualifying the actual pair and completing the pending Fable review. The lab result applies to the tested firmware, topology and synchronization mode; it does not qualify legacy writers or every firewall feature.

## Reproduction sequence

1. Restore and sanitize two appliances; assign distinct MAC, SSH and host identities. Create isolated LAN/WAN/sync networks and confirm there is no route to production.
2. Configure CARP on LAN/WAN, permit protocol 112, and configure pfsync plus one-way XMLRPC with only aliases/rules/NAT selected.
3. Use the plugin with `read_only:false` and `ha_sync_mode:xmlrpc_pf` only against that pair. Run alias, rule and DNAT CRUD; inspect both nodes and send independent packets.
4. Exercise stale revision, invalid upstream input, denied permission and split/missing peer states. Verify denied writes leave no object.
5. Flush storage, establish a TCP connection without automatic reconnect, hard-stop the primary, and verify both the existing connection and fresh connections through the backup.
6. Restore the primary; delete the objects, inspect both nodes, fail over again and verify fresh connections are blocked. Remove all test objects and stop the temporary appliances and access processes.
